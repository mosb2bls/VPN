# ADR-0001: TypeScript bindings via tauri-specta

- Status: accepted (Phase B1, 2026-10-11)
- Context: The UI must be built against a compiler-enforced contract (SPEC §5 of the
  brief). Options: `ts-rs` (types only; command wrappers and event names hand-written)
  or `tauri-specta` (types + typed command wrappers + typed events from one builder).

## Decision

Use `tauri-specta =2.0.0-rc.25` with `specta =2.0.0-rc.25` and
`specta-typescript =0.0.12`, pinned exactly (`=`), as the crate itself requires during its
RC period (crate docs: "it is really important you use `=` before your Specta version").

- Builder in `src-tauri/src/api/mod.rs` (`specta_builder()`), used both at runtime
  (`invoke_handler`, `mount_events`) and for export, so registered commands and exported
  bindings cannot diverge.
- Output: `src/api/bindings.ts`, generated by `npm run gen:bindings`
  (`UPDATE_BINDINGS=1 cargo test -p edge-app --lib bindings_are_current`).
- Without `UPDATE_BINDINGS`, the same test **fails if the committed file is stale**, so
  `cargo test` (and CI in B6) enforces regeneration. Bindings are not written on
  `tauri dev` startup, to avoid surprise churn in the UI agent's hot-reload.
- Error mode: `ErrorHandlingMode::Result` (default) — every command resolves to
  `{status:"ok",data} | {status:"error",error: AppError}`.
- specta-typescript forbids 64-bit integers (BigInt) by default (crate error docs,
  "BigInt Forbidden"); the API therefore uses `u16`/`u32` and `f64` for byte totals. We do
  not enable `dangerously_cast_bigints_to_number`.

## Consequences

- RC dependency: upgrades must bump all three crates together and regenerate bindings.
- Wire shapes of tagged unions are pinned by a serde test
  (`api::types::tests::tagged_union_wire_shapes`).
