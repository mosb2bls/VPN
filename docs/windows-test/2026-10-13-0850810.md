## Failures

### F-3: the app refuses the real helper — "pipe server is not the installed helper" (all TUN features still dead)
- Steps: install the helper from the app (UAC accepted; service running, pipe present). `get_helper_status`, or `connect`
  in TUN mode.
- Expected: `running: true` with a version; TUN connects.
- Actual: `running: false, version: null`; `connect` → `HELPER_AUTH_FAILED`, detail `pipe server is not the installed helper`.
- Evidence (same normal user, outside the app): `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION, FALSE, <helper service
  PID>)` → **fails, error 5 (access denied)**. The same call on the user's own process works.
- Cause: `src-tauri/src/net/helper_client.rs:59` verifies the pipe server with `GetNamedPipeServerProcessId` →
  `edge_winsys::process::image_path` (`crates/winsys/src/process.rs:13`, `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)`
  + `QueryFullProcessImageNameW`). The helper runs as **LocalSystem**; its process DACL does not grant the interactive user
  (a split-token administrator running at medium integrity, i.e. not elevated) that right, so `image_path` returns `None`
  and the check fails closed. The round-1 CI pipe test ran its server as the same user, so it could not catch this.
- Suggested fix (backend decides): verify by **PID instead of image path** — `QueryServiceStatusEx(SC_STATUS_PROCESS_INFO)`
  on `io.github.mosb2bls.edgeclient.helper` (needs only `SERVICE_QUERY_STATUS`, which users have) gives the service's
  `dwProcessId`; accept the pipe only if it equals `GetNamedPipeServerProcessId`. The service's binary path can only be
  changed by administrators, so this keeps the anti-squatting guarantee. Alternative: the helper adds an ACE for the
  installing user's SID (`PROCESS_QUERY_LIMITED_INFORMATION`) to its own process DACL at start-up. Either way a CI test
  should run the server **as a service / as SYSTEM**, or the check should be covered by the Windows checklist only.
- Severity: **blocker** (W-HELPER 2, W-TUN, W-DNSLEAK, W-IPV6, W-KILL, W-FORCEKILL 3, W-RESTORE TUN, W-RESTORE-PARTIAL,
  W-REBOOT TUN, W-INSTALL 4)
- Owner: backend

### Observations
- **O-1 (backend):** upgrading the app leaves the previously installed helper running with the **old** binary, and the
  app does not flag it (`needsUpgrade: false`, because no version could be read). Once F-3 is fixed, please make sure an
  older helper is reported as `needsUpgrade: true` (version mismatch or unreadable version while the service runs), so the
  user gets a "reinstall helper" prompt after an upgrade. Retest in round 3 by upgrading over this build.
- **O-2 (UI / backend, low):** the popover window measures 340×452 before it has ever been shown and 340×480 once shown
  from the tray. Fine if intentional (resized on show); otherwise make the initial window size 340×480.
